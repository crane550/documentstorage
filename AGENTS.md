# Working on DocumentStorage

Guiding principle, **configure by using** (Alex, 5 Nov 2026): the structure is built while doing the work, not in a setup step. Every place a person corrects something should offer to keep that correction (a field kept for its kind, a field put into the name or folder, a spelling kept for a sender, a regular trusted). Prefer a small inline button on the slip to a settings page; settings pages are for review and tidying.

Read docs/direction.md and docs/sorting.md first: they set the current direction (the inbox-to-folder loop) and override older priorities below. Then README.md, docs/product-plan.md, docs/intake-and-rules.md, docs/local-ai.md and docs/assistants-and-mcp.md first. This is the document application; `/workspace/2FAAccounts` is a read-only stack/deployment reference, not our app. Use the existing checkout; cloud tasks are isolated, so do not create worktrees unless asked.

Keep the product name configurable and provisional. Preserve the cardboard palette and file/folder-centered interface. Read docs/interface.md before changing the UI: pages are real routes over the shared `WorkspaceState`, the filing loop runs Inbox → AI suggestion → approval, with optional rules, and browser checks share their steps through tests/browser/ui.mjs. Use synthetic documents only. Keep actual documents, OCR text, secrets, database backups and machine paths out of commits.

All filesystem mutations belong in Core so future UI and MCP clients share validation, collision checks, journaling and recovery. Never overwrite an existing document or interpret offline storage as deletion. Scanning/extraction must not let document contents become instructions. Generate EF migrations with the pinned dotnet-ef tool. Filing previews must revalidate fingerprints, actor identity, expiry, all matching rules and stored revisions before moving bytes; keep filing and recovery on the same writer gate/journal. Enabling a rule does not enable unattended filing. Unattended filing exists only for sorting: a kind or a regular (one kind from one sender) the person switched to "file without asking", a sure reading or a sure fill-in from that regular's memory, untouched details, the master switch on, never a document whose filing was undone, and always undoable; never widen it without the person.

Validate changes with a Release solution build and the relevant real PostgreSQL/filesystem checks. For UI behavior run tests/browser against a disposable local catalog. The check runner drops only loopback databases ending _checks. Do not treat a build, health response or prerendered page as proof interactive filing works.

Origins stay on loopback. Use the same built-in ASP.NET Identity username/password and cookie login pattern as the accounting app. Cloudflare Tunnel is transport only; never require Access team/Audience configuration. Keep the root, downloads and Blazor transport protected, and login/logout/password forms protected by antiforgery. Run tests/DocumentStorage.AuthenticationChecks for hosting changes. Windows install/update scripts are in tools/deploy; their actual service/ACL behavior still needs server validation. NAS migration, bounded filesystem/bulk MCP operations, per-folder grants remain later milestones. Browser updates use a fixed installed Windows task; preserve cookie-only administrator/antiforgery checks, exact checked commit approval, durable requests and backup/rollback. See docs/updating.md; never add arbitrary commands or MCP deployment tools. Ollama identification is implemented and off by default; keep its responses as separate proposals, require explicit human review, and reject stale source/review/settings/context bindings. Never send OCR before checking model metadata for cloud backing. Validate changes with the protocol fixture and real queue checks; do not claim model accuracy from a fixture. Do not present roadmap controls as working AI.

MCP uses the official SDK and OpenIddict, with the existing app login for consent. Keep bearer authentication isolated from browser cookies, enforce scopes for discovery and calls, and recheck connection/account revocation. Use the actual authenticated subject/connection; never take actors or grants from tool arguments. Proposals require current context/target hashes and idempotency keys. Keep public snake-case DTOs and result schemas separate from EF entities. Source messages/versions and external rule source requests must remain traceable. MCP cannot approve proposals or mark facts human-reviewed. Alex clarified on 7 Nov 2026: verification is the goal, not requiring approval of every AI edit. Explicitly granted sorting.manage permits metadata/training edits through review-first or apply-then-verify, with apply_now for an explicit go-ahead. Preserve before/after receipts and user-only verification; never widen file-moving or unattended-filing authority. Diagnostic assistant readings must never auto-file. Approved filing must revalidate under the existing writer and commit proposal completion/audit with the journal, including recovery. Run DocumentStorage.McpChecks and the relevant browser workflow for these changes. Never print client secrets, bearer/refresh tokens or document text in logs/artifacts.

Recovery decisions change catalog/journal only; never delete either disk copy, auto-adopt legacy target-only operations, or let manual recovery override a filing fingerprint. New moves persist bounded source snapshots and verify the complete result. Inspections must bind the actor, expiry, both content digests and catalog state, and revalidate under the shared writer. Commit the catalog, journal, linked filing/proposal state and recovery receipt together. Cancelled filing approvals cannot be retried. Missing/offline/unsafe paths are distinct; dangling links are unsafe. Recovery scanning can discover a leftover copy as a new identity, while internal trash copies remain preserved outside the library. Run RecoveryChecks (including save-fault/OS-race fixtures), auth/MCP checks, and the seeded recovery browser workflow after changing these boundaries. The destructive standalone RecoveryFixture is limited to loopback *_recovery_checks catalogs and synthetic ignored storage; it is never a production endpoint.

Previews use vendored, pinned PDF.js assets; rebuild them through tools/preview-assets and retain licenses. Scope PDF.js styles to .document-preview. Preview routes use the existing cookie login, root/entry checks and metadata revision binding, explicit MIME/signature checks and nosniff/no-store. HTML, SVG and Markdown are escaped source text, never app-origin active content. PDF scripting, editing and active annotation widgets stay disabled; retain static annotation appearances. Dispose render tasks/workers/listeners/blob URLs on switching. Verify actual PDF pixels, controls, protected byte ranges, text escaping, mobile layout and existing Intake workflow; a canvas element alone is not proof of rendering.

Feature priority: docs/feature-roadmap.md (the sorting loop; conversations, folder planning and PDF tools are parked). The local model classifies and extracts; code builds folders and names through kind patterns (SortPatterns), never model-supplied paths. Conversations are actor-owned; source quotes/IDs/pages must be grounded in retrieved indexed passages. Share the model inference slot with identification/guidance. Folder plans create/reuse scoped directories and canonical notes only, never arbitrary moves/deletes. Preserve per-step ownership proof and scanner exclusion until interrupted creations resolve; cancellation preserves directories. See docs/conversations.md.

Baseline: version 0.3.040 is `f9555ad`, tagged `v0.3.040`; start future work from current `main`, never the earlier 0.3.022 checkout. `main` is the sole working branch (Alex, 7 Nov 2026); do not create feature branches.

Git: when a change is finished and its checks pass, merge it into `main` and push `main` (Alex, 5 Nov 2026: "always do this"). Fetch first and keep local `main` current. If remote `main` advances during work, integrate it without rewriting history, resolve and re-run affected checks before pushing.
