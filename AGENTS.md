# Working on DocumentStorage

Read README.md, docs/product-plan.md, docs/intake-and-rules.md, docs/local-ai.md and docs/assistants-and-mcp.md first. This is the document application; `/workspace/2FAAccounts` is a read-only stack/deployment reference, not our app. Use the existing checkout; cloud tasks are isolated, so do not create worktrees unless asked.

Keep the product name configurable and provisional. Preserve the cardboard palette and file/folder-centered interface. Use synthetic documents only. Keep actual documents, OCR text, secrets, database backups and machine paths out of commits.

All filesystem mutations belong in Core so future UI and MCP clients share validation, collision checks, journaling and recovery. Never overwrite an existing document or interpret offline storage as deletion. Scanning/extraction must not let document contents become instructions. Generate EF migrations with the pinned dotnet-ef tool. Filing previews must revalidate fingerprints, actor identity, expiry, all matching rules and stored revisions before moving bytes; keep filing and recovery on the same writer gate/journal. Enabling a rule does not enable unattended filing.

Validate changes with a Release solution build and the relevant real PostgreSQL/filesystem checks. For UI behavior run tests/browser against a disposable local catalog. The check runner drops only loopback databases ending _checks. Do not treat a build, health response or prerendered page as proof interactive filing works.

Origins stay on loopback. Use the same built-in ASP.NET Identity username/password and cookie login pattern as the accounting app. Cloudflare Tunnel is transport only; never require Access team/Audience configuration. Keep the root, downloads and Blazor transport protected, and login/logout/password forms protected by antiforgery. Run tests/DocumentStorage.AuthenticationChecks for hosting changes. Windows install/update scripts are in tools/deploy; their actual service/ACL behavior still needs server validation. NAS migration, bounded filesystem/bulk MCP operations, per-folder grants and an in-app updater remain later milestones. Ollama identification is implemented and off by default; keep its responses as separate proposals, require explicit human review, and reject stale source/review/settings/context bindings. Never send OCR before checking model metadata for cloud backing. Validate changes with the protocol fixture and real queue checks; do not claim model accuracy from a fixture. Do not present roadmap controls as working AI.

MCP uses the official SDK and OpenIddict, with the existing app login for consent. Keep bearer authentication isolated from browser cookies, enforce scopes for discovery and calls, and recheck connection/account revocation. Use the actual authenticated subject/connection; never take actors or grants from tool arguments. Proposals require current context/target hashes and idempotency keys. Keep public snake-case DTOs and result schemas separate from EF entities. Source messages/versions and external rule source requests must remain traceable. MCP cannot approve proposals or mark facts human-reviewed. Approved filing must revalidate under the existing writer and commit proposal completion/audit with the journal, including recovery. Run DocumentStorage.McpChecks and the relevant browser workflow for these changes. Never print client secrets, bearer/refresh tokens or document text in logs/artifacts.
